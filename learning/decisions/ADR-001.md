# ADR-001: bounded local optimization experiments

- Date: 2026-11-11
- Status: Accepted for the local Toy Runtime only
- Scope: `experiments/toy_agent/runtime.py`; not Google Harness² or a real coding benchmark

## Context

The Stage 03 review found an allowed-tool gap (`dev-08`) and a one-step stopping boundary (`val-05`). Stage 01 also has a real local timeout test. A scripted final answer in `val-04` is wrong despite a correct tool result. These observations suggest distinct hypotheses; they do not imply one universal fix.

## Decision

1. Keep the global tool schema strict. Accept an optional per-task `allowed_tools` set and reject a forbidden call before dispatch. The attempted call stays in the trace. A correct final answer cannot excuse a policy violation.
2. Allow at most three retries only for locally pure `add` and `uppercase`, and only after a `tool_timeout`. Use bounded exponential delay. The default remains zero retries. The trace records total execution attempts when a retry occurs.
3. Treat `max_steps` as a measured configuration variable. Increase it only with paired task evidence and an explicit safety check; a larger budget can expose unsafe scripted decisions.
4. Keep prompt and tool-description changes as hypotheses until a model-backed, controlled comparison is authorized. `FakeModel` consumes preset decisions and cannot validate prompt efficacy.

## Consequences and limits

- The allowlist may turn a previously `completed` local contract into `unauthorized_tool`; this is expected safety enforcement, not evidence of lower model capability.
- Retry adds latency and can duplicate an action if a timeout occurs after a side effect. `delay` is not retried, and a future refund/message tool must require idempotency keys or human confirmation before any retry policy.
- The Stage 02 runner does not yet pass its case allowlist to `run_agent`; its historical artifacts remain comparable. The Stage 05 probe passes the allowlist directly to test the new boundary.
- No claim is made about actual LLM reasoning, SWE-bench resolution, API cost, or population-level improvement. A small synthetic probe only verifies code behavior.

## Verification

`python -m experiments.evaluators.optimization_loop --output reports/stage05_optimization_probes.json` saves six local contrasts. Runtime and evaluator regression tests check blocked dispatch, bounded backoff, no retry for `delay` or schema errors, exhaustion, budget behavior, and the apparent completion gain with an unauthorized call. See `reports/optimization_loop.md` for observed values.
