## 本阶段要学会解释的概念

- 已系统讲解评测任务、数据集、Prediction、Trace、原生判题器、`resolved/failed/infra_error/unscored`、有效评分成功率与评分覆盖率。用户正确手算 `8/(8+8)=50%` 和 `16/20=80%`，能区分基础设施异常，并追问 SWE-bench 接入、判题、Trace 关联与报告生成。
- 已定点补充：Trace 解释过程但不能代替判题；新旧版本必须按相同任务 ID 逐题比较，不能只比较总体成功率。用户表示理解“我们在原生判题结果之上结合 Runtime Trace 做分析”，并要求提交 Stage 02 PR。尚未独立阅读本轮新代码或手算五条真实结果，不写成全面面试掌握。
- Pass@1 是一次尝试的通过比例；pass@k 是同题允许最多 k 次尝试时至少一次通过的比例，必须报告采样/预算/去重规则，不能与单次成功率直接混称。此阶段没有重复真实模型采样，因此**未测量 pass@k**。
- 24 条小型案例分 dev/validation/local-held-out；这是本地教学切分，不证明模型训练时未见过题。样本少且全由 FakeModel 脚本驱动，不报告置信区间或总体提升。

## Codex 实现的代码与工程证据

- `experiments/datasets/stage02_multitool_cases.jsonl`：24 条含 `case_id, input, split, expected_outcome, tool_constraints, tags` 的案例，覆盖 normal/boundary/error/permission/attack；`stage02_fake_decisions.jsonl` 单独保存脚本决策。
- `experiments/evaluators/metrics.py:TaskResult/summarize`：先校验 ID、状态、调用数和延迟，再按已评分任务计算成功率，按全部任务计算覆盖率，按已观察到的工具调用计算输入 Schema 有效率与越权尝试率；分母为零返回 `None`，不伪造 0%。
- `experiments/evaluators/stage02_demo.py:run_suite/run_case/tool_counts`：把案例输入送入 Stage 01 `run_agent()`；本地脚本契约给出 verdict；从 Trace 提取工具调用并按案例 allowlist 计数。模拟 `infra_error/unscored` 是明确的 fixture，不是真实环境故障。
- `experiments/evaluators/test_metrics.py` 与 `test_stage02_demo.py`：13 项测试，覆盖四种状态、空分母、非法输入、重复 ID、缺失延迟、越权但答案正确、多工具调用、全套案例与数据切分。
- 结果 JSONL：`reports/stage02_fake_results.jsonl`；命令、数字、反例和限制见 `reports/stage02_metrics_smoke.md`。
