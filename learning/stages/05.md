## 本阶段要学会解释的概念

- Bad Case → 可证伪假设 → 单变量对照 → 逐题结果与过程安全检查 → 接受、人工审阅或拒绝。
- Prompt 指令、Tool Schema 类型契约、按任务工具 allowlist、Runtime 决策步数、仅对幂等纯工具的限次重试、指数退避、超时后的未知执行状态、回归测试与 ADR。
- FakeModel 的预置决策不会因 prompt 改写而推理变化；本阶段的结果只证明本地代码边界，不证明真实模型或公开 Benchmark 效果。

## Codex 实现的代码与用户独立理解/验收证据

- `experiments/toy_agent/runtime.py`：按任务 allowlist 在执行前拒绝越权工具；纯 `add`/`uppercase` 遇 `tool_timeout` 可配置 0–3 次重试，指数退避，Trace 留执行尝试次数。默认行为保持零重试、无新增任务 allowlist；旧 Stage 02 运行契约不被静默重定义。
- `experiments/evaluators/optimization_loop.py`：用现有 `val-04`、`dev-08` 和由 `val-05` 派生的新案例做六组单变量本地探针，原始结果保存在 `reports/stage05_optimization_probes.json`。工具 Schema 的错误类型仅做拒绝控制，不伪称提示词或描述优化有效。
- 决策与限制见 `learning/decisions/ADR-001.md`、`reports/optimization_loop.md`。用户尚未回答本阶段思考题或验收新代码。

## 真实实验与运行命令

- `python -m experiments.evaluators.optimization_loop --output reports/stage05_optimization_probes.json`：六组本地探针完成。
- `python -m unittest discover -s experiments/toy_agent -p test_runtime.py`：12 项通过；`python -m unittest discover -s experiments/evaluators -p test_*.py`：29 项通过（2026-11-11 初次验证；最终提交前复跑）。
- `max_steps=1→2` 在指定新案例生成 final；纯工具超时重试在注入的第一次超时后恢复。`max_steps=1→3` 的另一案例虽然生成 final，但执行越权 `uppercase`，应拒绝采用。Prompt 改写无变化；没有真实 LLM、SWE-bench、付费 API、token/cost 数据或总体提升结论。

## Bad Case / 调试证据

- `dev-08`：原本执行了不在任务 allowlist 的 `uppercase`；新策略在 dispatch 前拒绝，Trace 保留尝试但执行次数为 0。
- `val-04`：工具返回 4、FakeModel 最终给 5；改写 prompt 不改变预置决策，真实 prompt 假设仍未验证。
- `val-05`：原任务预期就是一步预算触发 `max_steps`，未改写原标签；新派生任务专门比较一步与两步预算。
- `stage05-budget-unsafe`：提高预算让完成状态变好，同时暴露越权调用，展示为何要同时看 outcome 与 trajectory。
